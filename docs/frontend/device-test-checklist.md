# 실기기 테스트 목록

웹 미리보기 · 스토리북 · jest 로는 확인할 수 없어서 **폰(개발 빌드)에서 한 번에 볼 것**을 모아 둔다.
항목을 더할 때: 무엇을 · 왜 웹으로는 안 되는지 · 어떻게 재현하는지 · 언제 · 관련 커밋을 적는다.
확인하면 `[x]` 와 날짜 · 기기(예: iPhone 15 / iOS 18, Galaxy S23 / Android 14) · 결과를 남기고, 문제가 있으면 따로 고친 뒤 커밋을 적는다.

## 대기

- [ ] **새 배지 축하 시트 · 배지 푸시** (2026-11-28, 미커밋)
  - 왜: 시트가 탭 화면 위에 저절로 뜨는 흐름(iOS Modal 겹침) · 앞으로 돌아올 때 다시 묻기 · FCM 푸시는 웹 미리보기로 재현이 안 된다. 가짜 서버는 안 본 배지가 늘 없다.
  - 준비: mock 끄고 dev 서버(`migration-app-badges.sql` · `migration-app-badge-awards.sql` 적용), 콘솔에서 '번개 1회' 같은 배지를 VISIBLE 로 하나 만들고 그림(256×256 PNG) 올리기.
  - 재현 ① 앱을 켠 채: 다른 기기 · 콘솔로 이 계정의 번개 참여를 승인 → 푸시 배너 → 홈 탭 위에 축하 시트(그림 · 이름 · 설명) · 팡파르 → [좋아요] → 다시 안 뜬다. 마이 탭 배지 칸 · 개수가 바로 바뀌는지.
  - 재현 ② 겹친 화면 도중: 레슨 · 글쓰기 화면을 연 채로 받기 → 그 화면 위엔 안 뜨고, 닫고 탭으로 돌아오면 뜬다.
  - 재현 ③ 앱이 뒤에 있을 때: OS 알림 → 누르면 마이 탭 + 축하 시트. 푸시를 끈 계정은 앱을 앞으로 가져오면 시트가 뜬다.
  - 재현 ④ 두 개 한꺼번에: '새 배지 2개를 받았어요'에 두 칸, 끌어내려 닫아도 본 것으로 남는지(앱 다시 켜도 안 뜸).

- [ ] **iPhone: 시작 팝업 위에 반려 팝업이 겹쳐 뜨는지** (2026-11-26, `da12274a0`)
  - 왜: iPhone 은 떠 있는 창(Modal) 위에 다른 창을 띄우려면 그 창 '안'에 있어야 한다(`src/components/ui/sheet-stack.tsx`). 시작 팝업(`launch-popup.tsx`)과 반려 팝업(`link-rejected-popup.tsx`)은 둘 다 `LayerModal` — 웹 · 안드로이드엔 이 제약이 없어 웹에서는 확인할 수 없다.
  - 재현: 연동 요청 요약(`GET /me/branch-summary`) 응답이 0.9초보다 늦게 오게 해서(mock 이면 `?mockDelay=1500`) 시작 팝업이 먼저 뜨게 → 그 위에 반려 팝업이 보이는지 → [확인] 뒤 아래 시작 팝업이 그대로 보이고 눌리는지.
  - 기대: 두 팝업이 모두 보인다(순서는 상관없음). 반려 팝업이 안 보이거나, 그 뒤로 버튼이 안 눌리면 실패.
- [ ] **안드로이드: 반려 팝업에서 뒤로 키** (2026-11-26, `da12274a0`)
  - 기대: 팝업이 이번만 닫히고(확인 안 됨), 홈에 다시 들어오면 또 뜬다. 앱이 꺼지거나 화면이 뒤로 가면 실패.
- [ ] **카카오 로그인을 실제 키로 끝까지** (`8bfc739c6`)
  - 릴리스 노트에 "실제 키로 끝까지 해 보지는 않음". `.env.local` 의 `EXPO_PUBLIC_KAKAO_NATIVE_APP_KEY` 를 넣고 개발 빌드를 다시 만든 뒤, 카카오 앱 로그인 → 가입 단계 진입까지. 카카오 창을 닫으면 조용히 돌아오는지도.

- [ ] **푸시: 로그인 → 권한 → 토큰 등록 → 로그아웃 해제** (2026-11-26, 미커밋)
  - 왜: Firebase 는 네이티브 모듈이라 웹 미리보기에선 꺼져 있고(`push.web.ts`), iOS 는 시뮬레이터에서 토큰을 못 받는다.
  - 준비: Firebase 콘솔에서 `com.academy.pallo` 앱 2개 등록 → `google-services.json` · `GoogleService-Info.plist` 를 `mobile/` 에 → APNs 키(.p8) 업로드 → 개발 빌드 다시 만들기. mock 을 끄고 dev 서버에 붙인다(`migration-app-v2-push-tokens.sql` 적용된 DB).
  - 재현: 로그인 → 알림 권한 창이 뜨는지(Android 13+ · iOS) → 허용 → DB `mobile_push_tokens` 에 이 계정 · 기기 OS 로 한 행 → 앱 껐다 켜기(행 하나 그대로, `updated_at` 만 바뀜) → 로그아웃 → 행이 지워지는지. 거절하면 행이 안 생기는지.
  - 같은 기기에서 다른 계정으로 로그인하면 행의 계정이 바뀌는지도.

- [ ] **가입 단계 실연동: 실제 서버로 세 길 끝까지** (2026-11-26, 미커밋)
  - 왜: 웹 스토리북은 가짜 서버만 본다. mock 을 끄고 dev 서버(`migration-app-v2-onboarding.sql` · `migration-app-v2-trial-applications.sql` 적용)에 붙여야 확인된다.
  - 재현: 새 카카오 계정 → 약관(서버 현행 버전 · 전문 시트) → 닉네임(카카오 값 미리 채움) → 팔로로 → ① 지점 회원: 연동 요청 보내기 → 대기 → 시작하기 → 홈 / ② 체험: 지점 · 시간 고르고 예약 → 확인 → 앱 둘러보기 / ③ 앱 구경: 언어 · 이유 → 앱 둘러보기.
  - 기대: 보내기 한 번에 서버에 한 건(연동 요청 · 체험 신청 · 언어/이유), 실패하면 토스트만 뜨고 그 화면에 남는다. 확인 화면에서 앱을 껐다 켜면 홈으로 간다(서버는 이미 가입 완료).
- [ ] **지점 시트 지역 탭을 옆으로 밀기 (탭이 6개 이상)** (2026-11-26, 미커밋)
  - 기대: 탭 줄이 손가락으로 부드럽게 밀리고, 세로 스크롤과 엉키지 않는다. 연동된 · 확인 중 · 휴업 지점은 흐리게 막히고 눌리지 않는다.
- [ ] **앱에 그림이 없는 새 팔로로 (서버 그림 주소)** (2026-11-26, 미커밋)
  - 서버 카탈로그에 앱 번들에 없는 code 를 하나 넣고 캐릭터 화면을 연다. 기대: 그 칸 · 무대에 서버 그림이 뜬다(빈칸이면 실패).

- [ ] **가입 › 가장 가까운 지점: 위치 권한 · 거리순** (2026-11-26, `baea96a44` · `9c5112ef9`)
  - 왜: `expo-location` 은 네이티브 모듈이라 개발 빌드를 다시 만들어야 들어간다. 권한 팝업 · '다시 묻지 않음' · 설정 화면 갔다 오기는 웹으로 재현이 안 된다. 스토리북은 위치를 가짜로 끼운다.
  - 준비: 개발 빌드 다시 만들기(`app.json` 에 위치 권한 문구 추가). 실제 거리를 보려면 mock 을 끄고 지점 위경도가 채워진 dev 서버.
  - 재현 ① 처음 열기: 앱 구경 길 → 언어 · 이유 → 가까운 지점 화면 → 위치 권한 팝업(문구 '가까운 지점을 거리순으로…')이 뜨는지 → 허용 → '내 위치에서 가까운 순이에요' · 지점마다 방향 화살표 · '남동쪽 8.8km'.
  - 재현 ② 거절: 거절 → '위치 권한이 없어 지역별로 보여 드려요' + 지역별 목록 → [위치 켜기]. iOS 는 한 번 거절하면 다시 못 물어서 앱 설정이 열려야 한다 → 설정에서 허용하고 앱으로 돌아오면 저절로 가까운 순으로 바뀌는지. 안드로이드는 다시 묻는 팝업, '다시 묻지 않음'을 고른 뒤엔 앱 설정.
  - 재현 ③ 위치 꺼짐: 기기 위치 서비스를 끄고 열기 → 10초 안에 '위치를 찾지 못해…' + [다시 찾기]. 위치를 켜고 [다시 찾기] → 가까운 순.
  - 재현 ④ 옛 빌드: `expo-location` 이 없는 이전 개발 빌드에서 열면 앱이 죽지 않고 '위치를 찾지 못해…' + 지역별 목록.
  - 기대: 방향 화살표가 실제 지점 쪽을 가리키고(지도로 대조), 거리가 대략 맞는다. 좌표 없는 지점은 맨 뒤 빈 동그라미. 체험 · 연동 지점 시트는 위치를 묻지 않는다.
