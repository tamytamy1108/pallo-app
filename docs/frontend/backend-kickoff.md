# 백엔드 첫 회의 안건 (프론트 → 백엔드)

프론트는 **Expo(React Native) + TypeScript** 로 만들어요. 코드는 저장소의 `mobile/` 폴더예요.
이미 정리된 자료가 있어서, 회의 전에 백엔드 개발자에게 아래 자료를 먼저 보내요.

- `docs/PRD.md` — 기능 전체와 **9장 열린 질문** (특히 기술 Q-T1 ~ Q-T11)
- `docs/appendix/api-inventory.md` — 화면에서 거꾸로 뽑은 API 제안 목록
- `docs/frontend/api-additions.md` — 위 목록에 빠진 API 18개(A1 ~ A18) · 관리자 웹 API 개요 7묶음
- `docs/appendix/data-model.md` · `enum-dictionary.md` — 데이터 모양과 값 목록

회의에서는 아래만 정하면 프론트가 바로 움직일 수 있어요.

## 1. 꼭 정할 것 (프론트 작업이 여기에 걸려 있어요)

| # | 정할 것 | 프론트가 원하는 답 (제안) |
|---|---|---|
| B1 | 백엔드 언어 · 서버 | 무엇이든 괜찮아요. 아래 형식만 맞춰 주세요 |
| B2 | API 형식 | REST + JSON. **OpenAPI(Swagger) 문서**를 같이 만들어 주세요. 프론트가 타입을 자동으로 만들어 써요 |
| B3 | 개발 서버 주소 | 개발용 · 테스트용 주소를 따로. 실제 데이터와 섞이지 않게 |
| B4 | 로그인 · 토큰 | 카카오 · 애플 · 구글 (Q-T2). 토큰 유효 시간과 갱신(refresh) 방법 |
| B5 | 에러 형식 | 모든 에러를 같은 모양으로: `{ code, message }`. `message` 는 화면에 그대로 띄울 수 있는 한국어 |
| B6 | 목록 나눠 받기 | `cursor` 방식 (api-inventory 공통 가정과 같아요) |
| B7 | 시간 | 서버는 UTC로 주고, 화면 표시는 프론트가 기기 시간대로 바꿔요 |
| B8 | API 완성 순서 | 아래 3번 순서를 따라 주면 프론트가 막히지 않아요 |

## 2. 나중에 정해도 되는 것 (기능 만들 때)

- 사진 업로드: 서버가 업로드 주소를 주고 앱이 직접 올리는 방식(Q-T7)
- 실시간 채팅: 자체 서버 · 외부 서비스 (Q-T6)
- 푸시 알림: Expo 푸시 서비스를 쓰면 프론트가 가장 쉬워요. 서버는 기기 토큰만 저장하면 돼요
- 음성 · AI (Q-T4, Q-T5): 엔진이 정해지면 프론트는 녹음 파일을 보내고 결과를 받아요
- QR 출석 (Q-T3), 딥링크 주소 규칙 (Q-T9)

## 3. 작업 순서 제안

프론트는 **가짜 데이터로 먼저 화면을 다 만들고**, API가 하나씩 나오면 갈아 끼워요.
그래서 백엔드는 순서만 맞춰 주면 돼요.

1. 로그인 · `/me` (api-inventory 1 ~ 7)
2. 홈 · 출석 (8 ~ 15)
3. 라이브러리 · 학습 진도 (16 ~ 20 …)
4. 라운지 · 이벤트 · 마이
5. 푸시 · 채팅 · 음성 · AI

## 4. 일하는 규칙

- 저장소 하나에 `mobile/`(프론트) · 백엔드 폴더를 같이 둘지, 저장소를 나눌지 정해요.
- `main` 에 바로 올리지 않고 브랜치 → PR → 서로 확인 후 합쳐요.
- API 모양이 바뀌면 OpenAPI 문서부터 고치고 알려 줘요.
